# Organizer
## 1. DAO и репозиторий

Для работы с данными используется паттерн DAO.

Интерфейс `TaskDAO` содержит основные операции:

- получение всех задач;
- поиск задачи по ID;
- добавление;
- изменение;
- удаление.

Бизнес-логика не зависит от конкретного способа хранения данных и работает через интерфейс `TaskDAO`.

## 2. Три источника данных и Abstract Factory

В проекте реализовано три источника данных:

- `CollectionTaskDAO` - хранение данных в коллекции;
- `FileTaskDAO` - хранение данных в файле;
- `DatabaseTaskDAO` - хранение данных в SQLite.

Для создания DAO используется паттерн Abstract Factory.

Реализованы:

- `DAOFactory`;
- `CollectionDAOFactory`;
- `FileDAOFactory`;
- `DatabaseDAOFactory`.

Источник данных задаётся в `config.properties`:

```properties
datasource=collection
file.path=data/tasks.dat
database.url=jdbc:sqlite:data/organizer.db
````

## 3. Синхронизация источников

Кнопка `Синхронизировать источники` объединяет данные из коллекции, файла и базы данных.

Если задача с одинаковым ID существует в нескольких источниках, выбирается версия с самым новым значением `updatedAt`.

После этого актуальные данные записываются во все источники.

## 4. Логирование

В проекте используется `java.util.logging`.

Логируются основные действия:

* создание задачи;
* изменение задачи;
* удаление задачи;
* завершение задачи;
* запуск и завершение синхронизации.

Логи сохраняются в файл:

```text
logs/organizer.log
```

## 5. Mock-тесты

Для тестирования используются JUnit 5 и Mockito.

Mockito создаёт mock-объект `TaskDAO`, благодаря чему бизнес-логика тестируется без обращения к реальному хранилищу данных.

Проверяются:

* получение задач;
* создание;
* удаление;
* изменение статуса;
* поиск;
* сортировка;
* обработка отсутствующей задачи.
